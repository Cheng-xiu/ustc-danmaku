## 2. 已确定的技术分工

| 层 | 方案与职责 | 边界 |
| --- | --- | --- |
| 游戏核心 | C99/C11；既有 `packages/core/core/*.c` 与 `packages/core/ai/*.c` | 唯一裁决运动、扫掠命中、能量、攻击计划、学生脚本、随机数和终局 |
| 网页核心构建 | Emscripten 将同一批 C 源码编译成 Wasm | 不包含 EasyX、Win32 输入、窗口或原生日志文件代码 |
| 跨语言适配 | 薄 C 导出层 + TypeScript 客户端 | 明确版本、容量、有效期和错误状态；按批读取显示数据 |
| 游戏画面 | PixiJS 8.x，首版使用 WebGL | 只读显示快照；角色、弹幕、预警和视觉反馈均不裁决物理 |
| 网页交互 | TypeScript；菜单和 HUD 优先 HTML/CSS | 输入、布局、暂停、开始、重开和错误提示；不另写游戏规则 |
| 原生仿真与后续训练 | 同一 C 核心的原生无界面构建 | 可以按逻辑 tick 加速、重放和并行；不依赖 Pixi Ticker 或显示刷新率 |

前端使用 Vite；已冻结 PixiJS 8.22.0、TypeScript 5.9.3、Vite 7.1.12、Emscripten 6.0.11，实测 Node 24.19.0、npm 11.17.0，最低入口为 Node 22.12+/npm 10+。从根 `npm ci` 安装，提交唯一根锁文件；`npm run build` 依次构建 Wasm、Web、单文件，`npm test` 执行完整复验。分步命令见 monorepo 指南，不在应用内另建锁或另行安装。不得混用 PixiJS v7 与 v8 的初始化、Ticker 和粒子 API。

PixiJS 是 2D 渲染引擎，游戏流程需由项目组织；UI、音频等可按需要接入生态库。首版不引入通用 ECS、编辑器、重型 UI 框架或自制插件系统。若加入音频，遵守浏览器用户手势解锁要求，音效失败不阻塞游戏。

## 3. 迁移继续遵守的玩法

以下沿用提供的 Demo `docs/demo-rules.md` 中的已批准记录；接入源码时将完整规则记录纳入并核对，试验数值继续由同一 C 配置提供。

- 人类操作可移动 Boss，四招按住预瞄/松手发出，Space取消；共享能量自然恢复并封顶，成功请求扣一次，预瞄不扣，拒绝不扣、不排队。
- 鼠标朝指针位置移动、接近时减速，死区和键盘备用入口沿用基线；指针移出战场仍可操作，失焦/隐藏自动暂停。窗口铺满布局，仅顶部为 HUD；新局战场比例来自可用视口，逻辑面积保持 960×720，默认原生场地仍为 960×720。
- 同时只运行一招；接受时锁定手动方向、Boss原点和全部预警几何，攻击沿用同一计划，不再自动锁定最近学生。C纯预瞄不改世界/RNG/计划ID/事件；网页不得重抽或重新生成技能规则。
- 学生发射时瞄准 Boss 当时位置，直线弹不追踪；角色接触不伤害，普通弹不穿透，使用相对运动扫掠及已有稳定 ID 破平局规则。
- 默认无尽，仅 Boss 死亡判败；同一 tick 最后学生倒下也判败。清波不胜利，120 tick 出生预告后下一波 +1 人，上限 8，之后持续派 8 人。无强制时限，仿真 `max_ticks` 仅作实验截断，不能转换成胜负。
- GPA 只由累计真实击倒数计算：`floor(430*n/(n+20))/100`；部分伤害、时长、受伤和波次不计分。清波保留分数，死亡与截断冻结，重开清零。
- 普通攻击结束只清本招剩余 Boss 弹，学生弹按原寿命处理；清波额外清全部旧弹与计划，保留 Boss 血量、位置、能量和恢复余量，新波使用新学生 ID。
- 第 4 招消耗 100；四招与反击数值按用户本轮授权做统一配置对照和调参，现行参数集中在 [规则表](demo-rules.md)。
- 官方校徽圆形遮罩是显示操作；不更改碰撞半径、颜色或比例。单文件内嵌原图、Wasm 与代码，正式运行不依赖 CDN 或其他资源下载。
- 本轮使用已批准的直线基础运动，不启用默认场力、`ddl 逆转` 或擦弹计分；学生是可复现脚本，不宣称经过训练。

安全检查沿用接受时裁决，预警之后不复查并迁移几何。移动键优先鼠标移动；瞄准独立缓存且不随移动键旋转，这些已冻结事项不再作为未定需求。新玩法扩展仍先核查授权，必要时说明具体歧义；不要重问已批准的网页技术方案、按住释放、同步死亡、反击方向或时限。

## 4. 桥接、输入和时钟契约

### C/Wasm 接口

母代理在并行前冻结接口文档和 C/TS 共有类型。当前桥接提供初始化/重置、按尺寸初始化 `demo_reset_sized`、释放、固定 tick 推进、批量快照、`demo_step_aim`手动方向释放及`demo_preview`/`demo_preview_size`独立预瞄。原生和 Wasm 共用 `packages/core/sources.txt` 冻结的 16 个 C/AI 源文件，v6新增 `packages/core/core/pattern_aim.c`，与既有 `packages/core/core/field_config.c`一并由纯C编译。CMake 和脚本读取该清单，不另写完整列表。实际字段、导出和有效期以 [ABI v5](web-abi.md) 为准。

- 既有 `WorldView` 含指向核心内部的 C 指针，不能直接作为 JavaScript 对象。适配层导出活跃实体的连续数组、数量、血量/能量/攻击状态、公开预警和事件；不导出隐藏随机流或未公开的未来状态。已经公布的预警所需后续波次几何与时序允许只读投影；显示快照与 AI 观察分别规定可见字段。
- 固定容量与缓冲有效期写入契约；容量不足、版本不符或数据损坏须报错，不静默截断。`uint64_t` seed/实体 ID/计划 ID 使用高低两个 `uint32_t` 或明确 BigInt 契约，不能无条件转换成 JS `number`。
- TypeScript 从明确的偏移和布局读取数据，不猜 C 结构体对齐。Wasm 内存增长后重新建立 TypedArray 视图，跨帧保存的数据须复制或明确有效期。
- 每个 tick 推进后收集事件；同一显示帧追赶多个 tick 时汇总全部事件，不能只保留最后一个 tick。出招边沿消费一次，重复轮询不能复制一次按键。
- 前端按批读取快照，不对每一发弹逐字段调用导出函数。若公开预警信息不足，由核心提供只读几何投影，不在 TS 复制招式算法。
- 预瞄输出候选计划的真实 emitter rays，独立缓冲区不得覆盖已接受 warning缓存。busy/能量不足仍可提供几何，几何失败与无存活学生原因必须区分。释放采用同一工厂重新检查当前世界，原子扣费/锁定一次。

### 浏览器输入与唯一主循环

- 母代理维护唯一主循环。固定逻辑 60 Hz；显示帧可运行零个、一个或多个逻辑 tick，不能把 `Ticker.maxFPS=60` 当作固定物理时钟。
- 没有逻辑 tick 时保留未消费的出招边沿；追赶时只在约定 tick 消费，处理拒绝后不排队。暂停、重开、终局和失焦清理输入的方式需统一。
- hold selection是立即显示状态，release是单次逻辑输入，两者不能混用。Space取消selection和pendingrelease但保留WASD；owner匹配取消避免旧pointer误杀新key。释放包复制方向，随后鼠标移动不得改包；零tick帧照常调用纯预瞄和显示。
- CSS 缩放、DPR、Canvas 和顶栏尺寸通过同一屏幕到逻辑坐标转换处理；窗口级指针可以落在战场外，逻辑移动由核心夹紧角色边界。只有新局尺寸配置改变战场比例，局内布局变化不改当前物理或已接受计划。
- 页面隐藏时自动暂停；返回后显示暂停状态，由玩家继续。恢复清零时间积压，不补隐藏期间的逻辑，不出现骤然连发。
- 短暂掉帧可按有界策略追赶；超出预算时明确暂停/提示并清理时间积压，不悄悄改变 tick 长度、弹速或训练记录。预算属于实现配置，记录实测依据。
- 键盘、右键暂停、重开以及焦点恢复按实际浏览器行为验证；只在游戏交互区域处理必要的浏览器默认行为。

## 5. 渲染和性能起点

首版使用普通 Sprite 对象池和共享纹理/图集，按稳定实体身份更新；复用弹池槽位不等于复用整局 ID。预警读取 C 的公开几何，界面按状态变化更新，避免每帧重建全部 DOM、文字纹理和复杂 Graphics。

手动预瞄仅画C提供的第一波（或明确标注的后续波）rays、出生点和方向箭头，保持实际扫描空带，不用凸包填充。未就绪仍显示灰/红方向及C理由；层次在真实弹幕下，取消/重开清理缓存。当前线延伸到显示边界，实际攻击结束会清弹，不把弹道全长说成保证可达范围。性能检查另覆盖持续持有四招的C候选生成、解码及整帧开销。

先不依赖 WebGPU 或实验性 ParticleContainer。只有性能采样指向渲染瓶颈时，再采用粒子容器、专用批量绘制等措施。简单弹不逐个挂滤镜、交互事件、物理组件或独立更新回调。

800 发是当前池容量及压力检查目标，不是日常四招都会产生的弹量。压力夹具可以在单独测试场景中构造，必须标为夹具，不修改正式规则或当作实际对局证据。

不承诺“性能几乎不变”。分别记录 C 核心耗时、桥接/解码耗时、绘制及整帧耗时、帧时间分布、资源加载和内存；记录机器、浏览器、构建模式、分辨率、DPR、弹量和测试时长。网页首轮以目标设备流畅 60 FPS 为验证目标，不将“计数器显示 60”作为唯一性能证据。原生仿真吞吐单独报告。

## 7. 交付与验收门槛

1. 固定基线可复现，已有构建失败逐项记录；迁移不会自动解决历史问题。修复与网页改动分别留下原因和证据，不覆盖旧调试记录。
2. 干净环境能构建 Wasm、前端与单文件 HTML；正式交付必须通过双击 `file://` 离线试玩，不需要服务器、账号或资源下载。HTTP 静态版另作开发和部署检查，页面部署仍正确提供 Wasm MIME 类型和资源路径；普通单线程方案不依赖跨源隔离。
3. 完成四招、学生躲避与反击、真实命中、手动方向预瞄/释放/取消、共享能量、无尽派出、收敛 GPA、死亡、暂停及重开；验证同 tick 双倒判败和清波不胜利。临时桩和预录动画不算可玩版本。
4. 原生与 Wasm 在同配置、种子和逐 tick 输入下对照状态、事件及终态；比较稳定字段，不比较含指针/填充的结构体原始字节。浮点容差预先记录；离散事件/目标/胜负分歧视为失败，不扩大容差掩盖。
5. 实际检查零/多 tick帧的立即预瞄/一次释放、Space与旧owner松手、低能量/busy预瞄和拒绝、鼠标实际变化更新方向/静止不转向、拖按钮释放、鼠标进入顶栏/离开Canvas仍跟随、键盘覆盖移动、失焦/隐藏、尺寸切换、暂停恢复/重开/终局。按不同场地比例对照真实核心，不能用CSS或人工rays夹具替代；保留只读QA快照及真实输入方式说明。
6. Release 构建在明确设备/浏览器上采样常规对局和 800 发夹具，报告帧耗时及分层成本；无法达到目标时留下可复现问题，不写性能等价结论。
7. 交付源码、依赖锁、构建说明、离线单文件 HTML、操作说明和独立验收报告，可选 HTTP 静态版随源码保留。各版本调试与测量按版本记录；对外部署前确保产物和部署配置可供审查，不把“构建成功”写成“已发布”。

## 8. 对后续训练的影响

离线训练继续链接同一 C 核心的原生无界面构建，不让浏览器帧率或暂停决定训练时间。`apps/sim/` 脚本回放不是已经完成的 RL 环境；观察、动作、决策周期、奖励、重置、终止/实验截断、批量环境和模型导入仍须在后续阶段设计。

渲染快照只用于显示，不能直接代替学习观察。后续训练冻结核心、配置、对手策略和种子分组，依 [机器学习平衡规划](ai-balance-plan.md) 实施；网页用于真人试玩与回放展示。用户后续希望用训练更新更多的 AI 学生提升难度，但本轮仍是脚本学生，训练算法、奖励系数与更新定义尚未实施。技术迁移本身未批准训练方案；用户已另行授权本轮自行调试并平衡四招和人数难度，按证据完成统一配置调整。

v6的合法动作还包含主动方向和释放时机，后续环境不能把旧“最近学生自动目标”脚本当作等价策略。需冻结方向坐标、动作节拍及观察可见性，再设计训练接口；本轮只提供纯C手动输入和无副作用预瞄，不声称已完成训练环境。
