# 网页最小可玩版：工程验证

日期：2026-10-07。基线：用户提供的 Windows/EasyX Demo 提交 `753a9f6`，在独立 `demo/pixijs-playable` 工作树迁移。当前配置 v2、ABI v1。本轮实现、基础工程验证及静态包完成；真人玩法结论、跨设备与跨浏览器验收待开展。

原始主工作树及其未提交测试文件未改动；本轮核心修复与适配集中在新工作树。旧 Windows 报告保留为历史，不继承其通过结果。没有使用规划中的外部 DeepSeek 路由；本轮由 Codex 和三名子代理完成。

## 工具与构建

实测 Windows 11 Home 10.0.26200、Intel Core Ultra 9 275HX、RTX 5070 Laptop / Intel Graphics。Node 24.19.0、npm 11.17.0、TypeScript 5.9.3、Vite 7.1.12、PixiJS 8.22.0、Emscripten 6.0.11、MinGW GCC 8.1.0、CMake 4.4.4。浏览器为系统 Chrome 154.0.8037.93，Playwright 1.56.1，headless、视口 1440×1000、DPR 1、WebGL。未采集浏览器实际选用的 GPU，不能把列出的独显型号解释为渲染设备验证。

`npm ci` 安装锁定依赖，`tsc --noEmit` 与 Vite production 构建成功，Wasm 使用 `-O2`。核心构建入口读取同一份 14 文件 C 清单，不包含 EasyX。Wasm 输出约 46.6 KB，加载器约 6.5 KB，整份静态产物及指纹以交付 manifest 为准。

原生/Wasm 对照使用配置 v2，组合为 `(seedLo, seedHi, students)`：`(20261006,0,3)`、`(12345,0,1)`、`(2596069104,305419896,8)`，每组含初始快照及 3600 次输入；终局后的重复快照亦计入。不是 10,803 个活跃游戏 tick，也不代表跨所有编译器确定性已验证。

浏览器功能测试使用受控时钟以精确检查暂停、事件和终局；性能测试使用新建浏览器 context 的真实时钟，避免把 Playwright 模拟时间误记为真实性能。四招检查长按只接受一次、忙碌拒绝不扣、不补发；Esc 暂停、右键暂停、缩放后指针位置、指针离开、键盘备用、失焦自动暂停、继续不补积压、重开清预警缓存及结果后停步均通过。

`pagehide/pageshow` 的 BFCache 路径用带 `persisted=true` 的事件检查暂停、保留核心及显式继续后的 RAF 恢复；这是生命周期处理器验证，未验证浏览器是否实际将该页面收入 BFCache。`document.hidden` 分支静态检查，真实切换浏览器后台标签的测试仍待测。

## 本机性能样本及限制

常规对局选课表攻击，约 3.1 秒、515 显示帧、186 逻辑 tick。逻辑始终 60 Hz；本机显示回调约 164 Hz，因此不少显示帧推进零 tick。下表均为毫秒：

| 指标 | 中位数 | P95 | 最大 |
| --- | --- | --- | --- |
| RAF 间隔 | 6.10 | 6.20 | 6.30 |
| JS 整帧 CPU 工作 | 0.40 | 0.70 | 9.30 |
| C step 每显示帧合计 | 0.00 | 0.10 | 1.00 |
| 快照复制/解码每显示帧合计 | 0.00 | 0.20 | 0.50 |
| render 调用 CPU 工作 | 0.20 | 0.30 | 6.20 |

普通 Sprite 800 发夹具、960×720 战场、DPR 1：60 帧预热 + 300 样本；RAF 中位/P95 6.10/6.10 ms、最大 6.30 ms，JS 更新及提交绘制中位/P95 0.70/0.80 ms。

采样包含 JS 更新和绘制提交，不含 GPU 完成计时；未测显存、完整内存峰值、长时泄漏或资源冷加载耗时。Wasm 配置初始内存 16 MiB、增长上限 64 MiB，这是配置边界，不能当作整页实测占用。零 tick 帧及浏览器计时精度会使核心/解码中位数为 0，不能解释为没有成本。

这些短时 headless 样本支持本机可继续试玩；不能证明弱设备、真实窗口前后台或所有浏览器稳定 60 FPS，也不能证明与 EasyX 性能几乎不变。800 夹具只压渲染，不压 C 碰撞/AI 或整局；原生训练吞吐、原生图形对比、多种子完整难度测试另行开展。
