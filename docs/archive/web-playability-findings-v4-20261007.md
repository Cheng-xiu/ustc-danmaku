# 无尽 Demo 游戏性评估

当前可用的循环是「移动躲反击 → 选招/蓄能 → 击倒学生 → GPA 增长 → 更多学生入场」。配置 v4 已完成基于真实核心的数值调整；完整方法、前后对照、留出种子和建议见 [平衡报告](../web-balance-findings.md)。

## 当前判断

玩法足以验证操作、主动选招和逐波增员的思路。四招已经有不同适用场景：环弹稳定施压，课表更适合多人封路，金矿低耗追击，满能量淋浴用于广域压制。普通距离混招样本约20秒清首波，人数上升后更需要躲弹和选择场地位置。

这仍是验证设计的最小版本。脚本会利用重复的直线瞄准弹；150秒合法回放能保持满血。八人之后人数不再变化、学生策略也相同，持续目标主要剩下累积击倒。中低耗招在攻击期间能回够下一次费用，长期资源选择仍偏浅。自动回放不能判断玩家的理解、疲劳或重开意愿。

## 建议顺序

1. 增强每招的命中与击倒反馈，让玩家能判断为什么换招；先测试是否能区分“弹很多”与“招有效”。
2. 采集5–10名首次试玩者的首死时间、首个击倒、首波耗时与重开意愿，决定教学和起始难度。先保留当前数值作为共同基准。
3. 八人之后分段引入不同职责或更强的训练学生，公开标明阶段。迭代次数只是训练元数据，实际难度还需用表现和体验验证。
4. 继续比较贴脸、绕行、只用一招和混招；评估攻击锁定时间、能量恢复和回能奖励能否增加决策深度。
5. 后期 GPA 两位显示会有平台，但累计击倒仍增加。可增加击倒反馈或细化进度显示，继续保持 GPA 只由击倒数决定。

上述建议尚未实装，避免一轮加入多个新系统后无法归因。当前原始报告保留每个版本身份，旧有限局“胜率”不能代表无尽版。
