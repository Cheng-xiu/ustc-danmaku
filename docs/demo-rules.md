## 1 已批准规则

### 1.1 主玩法（来源：`docs/boss-mode-plan.md` 第 1、2、3 节；用户确认本轮实施）

- 玩家操作 Boss，攻击四招由玩家**主动**触发；不按就等待蓄能，**不自动轮换招式**。
- 单一共享能量条，按逻辑时间自然恢复并封顶；暂停时不恢复。
- 接受一次出招请求**扣一次**能量；不足则拒绝，拒绝不扣、不排队、不自动补发。
- 攻击流程固定为：接受请求 → 预警 → 攻击 → 可再次选招。**同一时间只执行一招**。
- 默认是**无尽游戏，没有胜利条件**。击倒本波全部学生进入下一波出生预告；Boss 血量耗尽判 Boss 败并结束。
- 四招使用玩家手动瞄准：按住数字键或技能按钮立即预瞄，松开才发出一次请求，空格取消；不自动选择最近学生作为目标。移动与保存的瞄准方向分开，玩家后退也能沿所选方向出招。
- 接受出招时锁定方向、Boss 原点及全部弹幕几何，预警与实际攻击读取同一份不可变计划；之后 Boss/学生移动、学生死亡及鼠标转向不迁移原点、不修改该招方向、不重抽几何。手动计划 target_id=0，仍须有存活学生才接受。
- 不得恢复：旧固定六秒选招窗口、旧默认招式循环、旧 `Q[36][4]`、固定上方 Boss、120 秒生存通关、学生自动向上射击。

### 1.2 输入设备与移动区域（用户答复 2026-10-06 / 07）

- 输入设备：**鼠标摇杆**。操控方式参照 florr.io / digdig.io：角色**朝鼠标指针所在位置移动**，离指针近则慢、抵达指针处即停；不是"按下点即圆心"的偏移式摇杆。
  - 死区 `12 px`：指针与角色距离小于死区时视为已到达，不移动（防止抖动）。
  - 鼠标在顶部 HUD 或战场外仍朝指针方向移动。浏览器只提供窗口内的位置；移出可观察区域后保留最后已知位置与方向，窗口失焦自动暂停并清空输入。
  - 有键盘移动时优先键盘，松开后恢复鼠标。窗口缩放后按当前显示变换重新投影指针，不继续使用过期逻辑坐标。
- 键盘等价入口（调试与无鼠标试玩）：`WASD` / 方向键为八方向移动，斜向归一化，斜向速度与直向相同。
- 出招与系统键：按住 `1`/`2`/`3`/`4` 对应四招预瞄，松开当前选择产生一次释放请求；也可按住顶部技能按钮、拖到战场后松手。`Space` 取消预瞄及尚未消费的释放请求，后续松手不发招；`Esc` 或鼠标右键暂停/继续；`R` 重开；退出用窗口关闭按钮。
- 选择立即显示，不等待逻辑 tick；长按不自动出招、不预扣能量。最新按下替换旧选择，旧按键/指针松手不释放新技能；旧指针捕获取消不清新键盘选择。能量不足或 CD 未结束时仍能预瞄，释放由 C 明确拒绝，不排队。
- 每次新选择先从当前 Boss 指向当前投影后的鼠标计算初始方向（超过12px）；持有期间瞄准方向独立缓存，只有实际屏幕鼠标坐标变化且离 Boss 超过 12 px 时按最新 Boss/投影更新。Boss 穿过静止指针、同坐标事件、WASD 移动及窗口缩放不会转动已保存方向。无有效鼠标朝向时选择采用最近非零键盘方向，再无输入默认向上。预瞄时移动不停，WASD 可以覆盖鼠标走位而不改瞄准。
- 界面铺满浏览器窗口，顶部显示明显的能量条、共享 CD 条/倒计时、状态与操作按钮；其余空间全部为战场。四招完整介绍放在开始菜单，开始后隐藏。
- 新局场地按当前战场宽高比 a 取 `W=sqrt(960*720*a)`、`H=sqrt(960*720/a)`，保留逻辑面积；共享 C 适配出生点、边界与弹幕几何。
- 用户明确选择：游戏中途改变窗口比例，本局等比缩放以保留圆形校徽和已接受计划；重开后再按新比例铺满。
- Boss 移动区域为 `x ∈ [22, W-22]`、`y ∈ [22, H-22]`；960×720 仍是原生默认及比较基线。
- Boss 命中判定半径 = 角色半径 `22 px`。

### 1.3 反击与实体交互（用户答复 2026-10-06；来源建议：提示词第四节）

- 学生每次发射时瞄准 **Boss 当时位置**，生成**直线弹，不追踪**。
- 角色之间接触**不造成伤害**；只有弹命中角色才扣血。
- 普通弹**不穿透**：弹命中一个目标后即移除。
- 多目标时按**最早扫掠交点**命中；同参数时按**稳定 ID 小者优先**。
- 高速弹必须做**相对运动线段扫掠**判定，不能只查端点。

### 1.4 同步死亡与时限（2026-10-07 无尽模式授权覆盖旧有限局）

- 同一 tick Boss 与最后一名学生同时倒下：**记 Boss 败**。该 tick 已发生的真实学生击倒仍计入 n 与 GPA，随后冻结；不进入下一波、不产生胜利或平局。
- 初版**不设强制对局时限**。`max_ticks` 仅是 sim 防卡住的实验截断，截断结果记为 `TRUNCATED/未完成`，不自动判胜或负。
- 终局之后逻辑停止，不再推进 tick、计分、回血或派学生；可重开。历史有限局仅作为显式 `endless_mode=false` 的回归夹具保留，不能用作默认产品或无尽计分验收。

### 1.5 四招映射、用途与档位（主题／用途沿用 2026-10-06；本轮数值集中调试）

| ID | 招式 | 档位与用途 | 消耗 |
| --- | --- | --- | --- |
| 0 | 桃李苑·绿色圆圈好辣 | 前向 160°近中距双弧环 | 25 |
| 1 | 选课系统·课表华容道 | 分列弹墙、多人封路 | 50 |
| 2 | 一教金矿·绩点淘金 | 单目标窄扇三连 | 20 |
| 3 | 期末总评·绩点淋浴 | 长周期全场扫描雨 | 100（用户指定） |

- 保留四个主题，手动几何覆盖旧自动锁定版：环与金矿从接受时 Boss 原点沿所选方向发射；课表和淋浴沿所选方向从场地对侧边界进入，按方向横轴投影分带/扫描，不固定顶部直落。全部 rays 由 C 生成，预瞄显示不得自行重建技能规则。
- 环的接受时 guard 为 20 px，任一存活学生中心距离 Boss 小于 20 px 则拒绝；金矿保留 120 px 禁用距离，任一存活学生（包括背后或扇形外）距离 Boss 小于 120 px 则拒绝。等于边界允许，死亡学生忽略；拒绝不扣能量。
- 预瞄是 C 纯候选计划的只读投影，不消费 RNG、不扣能量、不修改当前计划/ID/事件。能量或 CD 未就绪时保留可生成的候选几何并标灰/提示原因；几何无效时仍显示所选方向。松手由 C 重新按当前世界检查并原子接受，预瞄不是提前锁定的攻击。
- **一次攻击结束清本招剩余 Boss 弹**；学生反击弹不受影响，继续按寿命/出界处理（用户批准）。
- 各招预警和攻击时长可以不同；这些时长**不等于**旧固定选招窗口。顶部 CD 展示当前单招占用到 IDLE 的剩余时间，由 `start_tick + windup + active + 1 - tick` 计算；IDLE 才显示可出招，没有新增独立冷却。
- 清波时额外清除全部旧弹与当前攻击计划，包括学生反击弹；保留 Boss 血量、位置、能量及恢复余量、累计击倒与弹池世代。新波使用新学生 ID，禁止旧弹误认新学生。

### 1.8 技术约束（来源：原规范第八章、提示词第五节）

- 核心 `packages/core/core/*.c` 与 `packages/core/ai/*.c` 使用 C99/C11，必须由 C 编译器编译；禁止仅改扩展名后仍用 C++ 编译核心。
- 核心不含 EasyX、Windows 输入 API、窗口 API、墙钟查询、C++ 容器；核心内不绘图、不写日志文件。
- `apps/desktop/`、`apps/sim/`、测试及 `packages/wasm/` 链接同一 `packages/core/` 核心与规则配置，完整16源清单只维护在 `packages/core/sources.txt`。
- 逻辑 `60 Hz` 固定步长，`dt = 1/60`；整数 tick；暂停不调用推进函数。
- 核心使用固定容量数组与明确函数，不使用 ECS/插件框架/脚本语言。
- 随机数用 SplitMix64 派生 `world`/`bot`/`explore` 三流；不用墙钟或平台 `rand()`。
- 弹池 ID 整局唯一，不能用可复用下标充当整局 ID。

### 1.9 网页迁移技术决定（用户批准 2026-10-07）

- 当前网页方案为 **PixiJS + TypeScript + C/Wasm**，具体实施见 [网页规划](web-demo-plan.md) 和 [网页母代理提示词](web-demo-agent-prompt.md)。
- 原生图形入口 `apps/desktop/`、仿真 `apps/sim/`、测试和 Wasm 桥接必须使用同一批 C 核心及规则配置；`apps/web/` 的 TypeScript 不另写碰撞、招式、能量、AI 或胜负。
- PixiJS 首版用 WebGL；网页显示循环按固定 60 Hz 推进核心，批量读取快照，处理缩放、边沿输入、页面隐藏、暂停恢复和重开。
- 后续离线训练继续使用原生无界面 C 核心；训练环境接口仍待设计，不将网页帧率当作训练速度。
- 单文件 HTML 必须双击离线可玩，不要求玩家装 Node、Emscripten 或启动服务器；HTTP 静态版保留用于源码开发和托管。构建工具与运行依赖区分说明。
- 当前配置 v6、[Web ABI v5](web-abi.md)；新增手动方向释放与独立预瞄缓冲区。GPA 由 C 核心计算，桥接输出累计击倒、GPA 与半饱和参数，TS 只读显示。v1/v2 为迁移与修复历史，v3 为首版无尽，v5 为自动锁定的全屏四招版；[修复记录](web-core-fixes.md) 和旧验收不能代替当前版本验证。
- Boss 使用 [官方中科大校徽](ustc-emblem-source.md)。圆形遮罩对齐原图圆盘，去除方形白角，保持图案比例和配色；它只作用于显示，Boss 碰撞仍是半径 22 px 的圆。

### 1.10 无尽波次与难度递增（用户授权 2026-10-07）

- 产品初始 3 名学生。清波后下一波人数为 `min(初始人数 + 已清波数, 8)`：默认 3→4→5→6→7→8，之后每波持续派 8 人，直到 Boss 死亡。
- 清波后显示 120 tick（2 秒）出生预告；标记点位在进入预告时一次确定并冻结，预告结束后学生出生位置与公开标记一致。预告期不判胜，Boss 可以移动与恢复能量。
- 出生选择合法配置点并由固定网格补足，预告生成时与 Boss 中心距离至少 `Boss 半径 + 学生半径 + 60 px`，学生之间至少 `2×学生半径 + 20 px`。Boss 主动走入预告点不重新选点或延长等待；没有接触伤害。
- 新生学生重新初始化生命与脚本状态，出生后等完整 78 tick 发射冷却再反击；已公开的出生点不能因后来动作偷偷变化。
- 当前难度增加来自人数，学生仍是可复现脚本。未来改用离线训练更新更多的 AI 学生是后续方向，未实现或训练前不得写成已有模型或能力递增证据。

### 1.11 GPA：击倒数收敛函数（用户授权 2026-10-07）

累计真实击倒数 n 是 GPA 的**唯一自变量**，本轮使用 `GPA(n)=4.30*n/(n+20)`。它从 0 开始增长，越往后平均增长越慢，趋近 4.30；时长、受伤、命中但未击倒、波次和部署人数不参与计分。

C 核心的 `world_gpa_for_kills` 用 64 位整数计算 `gpa_hundredths=floor(430*n/(n+20))`，每次真实击倒从累计 n 重算，显示为 `gpa_hundredths/100`。不能累加逐次取整的增量；有限击倒数不会显示 4.30，分数接近上限时可能多次击倒后才增长 0.01。参数 `gpa_half_saturation_kills=20` 是当前试验起点，即击倒 20 人时为 2.15。

| 累计击倒 n | 显示 GPA |
| --- | --- |
| 0 | 0.00 |
| 1 | 0.20 |
| 3 | 0.56 |
| 10 | 1.43 |
| 20 | 2.15 |
| 50 | 3.07 |
| 100 | 3.58 |

每个学生真实倒下只计一次；重复弹、无敌期间命中和部分伤害不重复计分。清波保留累计 n；死亡或实验截断后冻结，重开清零并回到第一波。

### 2.5 四招几何（试验值；原规范参数作为比较起点）

| 招式 | 预警 | 攻击时长 | 弹速 | 波次 | 每波发数 | 几何约束 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 环弹 | 24 tick（0.4 s） | 90 tick（1.5 s） | 360 px/s | 2（间隔 0.3 s） | 24 | Boss 原点沿所选方向的前向 160°弧，含两端角；任一存活学生距离 <20 px 拒绝 |
| 1 课表 | 60 tick（1 s） | 240 tick（4 s） | 210 px/s | 2（间隔 1 s） | 24 | 方向横轴投影分三带、封两留一，两带各 12 发；从对侧边界 inset 100 px 进入，空带轮换 |
| 2 金矿 | 18 tick（0.3 s） | 75 tick（1.25 s） | 480 px/s | 3（间隔 0.3 s） | 9 | Boss 原点沿所选方向发 40°窄扇，含两端角；任一存活学生距离 <120 px 拒绝 |
| 3 淋浴 | 90 tick（1.5 s） | 330 tick（5.5 s） | 240 px/s | 5（间隔 0.4 s） | 按投影取整 | 方向横轴全投影扫描雨，密度目标 51 px，保留 120 px 空带，每波移动一个实际 pitch；对侧边界 inset 100 px |

环弹、课表、金矿的单招计划发数固定为 48 / 48 / 27；淋浴随方向/尺寸投影跨度改变。960×720 竖向淋浴每波 16 发、共 80 发，水平方向每波 11 发、共 55 发，45°方向每波 20 发、共 100 发。清波或 Boss 死亡可取消尚未生成的后续波；正常存活夹具逐波兑现公开计划。各招首波均在攻击期相对 0 秒生成，接受时锁定方向、全部几何和生成时刻，不因以后移动变更。

方向单位向量为 u=(ux,uy)，横轴为 v=(-uy,ux)，场地横向投影跨度 L=abs(uy)*W+abs(ux)*H。课表第一波空带由接受时 Boss 的横轴所在带确定，第二波向后一带循环；封锁半宽按投影带宽缩放并受弹半径约束。竖向 960×720 的 `lane_spread_px=140` 为基准，不把旧 340 px 空档推广到全部角度/比例。

淋浴可用跨度为 L-4r-120（r=6），按 51 px 目标间距取整发数，满足最小扫描弹数、空带重叠及容量约束，实际 pitch 因取整略变。两招 ray 与场地矩形相交后进入，短斜弦 inset 不超过半弦长；不能逐点夹紧而产生重叠弹。场地验证失败明确拒绝重开并保留旧世界，提示调整窗口。

预瞄线表示 C 提供的弹道方向；攻击结束清弹意味着不是整条到场地边界的线都可实际走到。各招第一波最长路程约 540 / 840 / 600 / 1320 px，后续波更短；实际碰撞、出界和 tick 边界继续由 C 判定。

v6 按本轮确认改为按住预瞄、松手释放及四招手动方向几何，费用、时序和学生反击沿用 v5。当前几何及输入/释放验证见 [v6 登记](validation/aim-v6.md)。[v5 平衡报告](web-balance-findings-v5.md) 仍是旧自动锁定版的实际历史结果，不证明新弹形已经平衡；需要真实 manual 输入的新对照与真人试玩。原 PDF、旧规则及证据保持原版本身份。
