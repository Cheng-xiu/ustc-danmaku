## 1 已批准规则

### 1.1 主玩法（来源：`docs/boss-mode-plan.md` 第 1、2、3 节；用户确认本轮实施）

- 玩家操作 Boss，攻击四招由玩家**主动**触发；不按就等待蓄能，**不自动轮换招式**。
- 单一共享能量条，按逻辑时间自然恢复并封顶；暂停时不恢复。
- 接受一次出招请求**扣一次**能量；不足则拒绝，拒绝不扣、不排队、不自动补发。
- 攻击流程固定为：接受请求 → 预警 → 攻击 → 可再次选招。**同一时间只执行一招**。
- 玩家血量耗尽前击倒全部学生 = Boss 胜；Boss 血量耗尽 = Boss 败。
- 目标自动选择最近的存活学生，并标出目标；移动与瞄准分离，玩家后退也能出招。
- 接受出招时锁定目标与该招几何，预警与实际攻击读取同一份不可变计划；目标移动或倒下不暗中换目标、不迁移原点、不重抽几何。
- 不得恢复：旧固定六秒选招窗口、旧默认招式循环、旧 `Q[36][4]`、固定上方 Boss、120 秒生存通关、学生自动向上射击。

### 1.2 输入设备与移动区域（用户答复 2026-10-06）

- 输入设备：**鼠标摇杆**。操控方式参照 florr.io / digdig.io：角色**朝鼠标指针所在位置移动**，离指针近则慢、抵达指针处即停；不是"按下点即圆心"的偏移式摇杆。
  - 死区 `12 px`：指针与角色距离小于死区时视为已到达，不移动（防止抖动）。
  - 指针不在窗口内或窗口失焦时视为无输入（停止移动）。
- 键盘等价入口（调试与无鼠标试玩）：`WASD` / 方向键为八方向移动，斜向归一化，斜向速度与直向相同。
- 出招与系统键：`1`/`2`/`3`/`4` 对应四招；`Esc` 或鼠标右键暂停/继续；`R` 重开；`Esc` 在结算界面返回/退出按实现，退出用窗口关闭按钮。
- 画面 `1280×720`，左侧逻辑战场 `960×720`，右侧 `320 px` 为 HUD。
- Boss 移动区域（母代理按批准战场与半径留边选定，见 2.1）：`x ∈ [22, 938]`，`y ∈ [22, 698]`。
- Boss 命中判定半径 = 角色半径 `22 px`。

### 1.3 反击与实体交互（用户答复 2026-10-06；来源建议：提示词第四节）

- 学生每次发射时瞄准 **Boss 当时位置**，生成**直线弹，不追踪**。
- 角色之间接触**不造成伤害**；只有弹命中角色才扣血。
- 普通弹**不穿透**：弹命中一个目标后即移除。
- 多目标时按**最早扫掠交点**命中；同参数时按**稳定 ID 小者优先**。
- 高速弹必须做**相对运动线段扫掠**判定，不能只查端点。

### 1.4 同步死亡与时限（用户答复 2026-10-06）

- 同一 tick Boss 与最后一名学生同时倒下：**记 Boss 胜**。
- 初版**不设强制对局时限**。`max_ticks` 仅是 sim 防卡住的实验截断，截断结果记为 `TRUNCATED/未完成`，不自动判胜或负。
- 终局之后逻辑停止，不再产生新事件；可重开。

### 1.5 四招映射、用途与档位（用户答复 2026-10-06）

| ID | 招式 | 档位与用途 | 消耗 |
| --- | --- | --- | --- |
| 0 | 桃李苑·绿色圆圈好辣 | 中消耗·周边压力 | 30 |
| 1 | 选课系统·课表华容道 | 中消耗·封路 | 35 |
| 2 | 一教金矿·绩点淘金 | 低消耗·追击/局部打击 | 15 |
| 3 | 期末总评·绩点淋浴 | 高消耗·多目标压制 | 60 |

- 保留四个主题与基本几何：环弹原点锁在接受时 Boss 位置；课表与淋浴沿批准顶部区域生成；矿点保持与学生的安全出生距离。
- **一次攻击结束清本招剩余 Boss 弹**；学生反击弹不受影响，继续按寿命/出界处理（用户批准）。
- 各招预警和攻击时长可以不同；这些时长**不等于**旧固定选招窗口。

### 1.6 场力与学生技能（用户答复 2026-10-06）

- Boss 弹走**明确批准的直线基础运动**，不启用原默认场力 `(Kr, Kt) = (+100, 0)`。
- 不启用 `ddl 逆转` 技能场，也不启用擦弹计分。
- 说明：这不表示"原场力已全部删除"，只表示本轮不启用；后续启用需先确认多学生技能场叠加与逐学生事件归属。

### 1.7 本轮明确延后（来源：提示词第三节）

GPA、压制率、复杂成绩单、固定四阶段难度、GA、强化学习、旧 `Q[36][4]`、四档训练快照、在线自适应、联网、排行榜、多学生 `ddl 逆转` 技能场、擦弹计分。
AI 学生使用可复现脚本，**不声称经过训练**。保留可复用的纯 C 核心，暂不建训练平台。

### 1.8 技术约束（来源：原规范第八章、提示词第五节）

- 核心 `core/*.c` 与 `ai/*.c` 使用 C99/C11，必须由 C 编译器编译；禁止仅改扩展名后仍用 C++ 编译核心。
- 核心不含 EasyX、Windows 输入 API、窗口 API、墙钟查询、C++ 容器；核心内不绘图、不写日志文件。
- `game`、`sim`、测试链接同一批核心源码，读取同一规则配置。
- 逻辑 `60 Hz` 固定步长，`dt = 1/60`；整数 tick；暂停不调用推进函数。
- 核心使用固定容量数组与明确函数，不使用 ECS/插件框架/脚本语言。
- 随机数用 SplitMix64 派生 `world`/`bot`/`explore` 三流；不用墙钟或平台 `rand()`。
- 弹池 ID 整局唯一，不能用可复用下标充当整局 ID。

### 1.9 网页迁移技术决定（用户批准 2026-10-07）

- 当前网页方案为 **PixiJS + TypeScript + C/Wasm**，具体实施见 [网页规划](web-demo-plan.md) 和 [网页母代理提示词](web-demo-agent-prompt.md)。
- 原生 `game`、`sim`、测试和新增 Wasm 前端必须使用同一批 C 核心及规则配置；TypeScript 不另写碰撞、招式、能量、AI 或胜负。
- PixiJS 首版用 WebGL；网页显示循环按固定 60 Hz 推进核心，批量读取快照，处理缩放、边沿输入、页面隐藏、暂停恢复和重开。
- 后续离线训练继续使用原生无界面 C 核心；训练环境接口仍待设计，不将网页帧率当作训练速度。
- v1 是迁移基线；当前 v2 保留默认三学生、能量和攻防数值，补齐第 4–8 名学生合法出生点，并修复四招相对 tick、课表顶部带、矿点安全拒绝及截断停止。见 [修复记录](web-core-fixes.md)。ABI 已冻结为 [v1](web-abi.md)，本轮结果见 [工程验证](web-demo-validation.md)；历史验收不能当成 Web 通过证据。

## 3 待确认（依赖它的实现保持待定）

| 事项 | 具体疑点 | 当前处理 |
| --- | --- | --- |
| 锁定出生点的后续冲突 | 学生预期间走入环弹/金矿的锁定出生位置时如何处理：是否补发、跳过、还是允许命中 | 基线在接受请求时检查几何，之后按公开预警的锁定计划生成；当前未做生成时安全复查或冲突诊断，不暗中改计划。是否新增处理待确认；**不接受无预警命中** |
| 穿透规则细化 | 已批准"普通弹不穿透、按最早交点和稳定 ID"；同一 tick 内同一发弹是否可能命中第二个目标 | 实现为命中即移除，不考虑二次命中；取得答复后更新 |
| 鼠标摇杆与键盘混用 | 两者同时输入时的优先级 | 实现为：鼠标在窗口内且移动幅度超死区时优先鼠标，否则用键盘轴；取得答复后更新 |
| 学生 AI 复杂策略 | 是否需要更复杂的躲避 | 本轮用两级脚本，不做搜索 |
