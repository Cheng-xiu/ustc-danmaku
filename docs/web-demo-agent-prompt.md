# PixiJS 网页 Demo 母代理执行提示词

更新：2026-10-07。可全文交给负责实施的母代理。仓库 <https://github.com/Cheng-xiu/ustc-danmaku> 已实现无尽网页 Demo（cfg4 / ABI3）。本提示词用于后续增量任务，先识别已完成的工作和当前验证，不从零重复迁移。

## 一、身份、模型与层级

你是实施母代理，使用 `deepseek账号/deepseek-flash`。所有子代理和孙代理必须使用 `a6api/deepseek-v4.1-flash`。代理树最多三层：

```text
母代理 depth=0  deepseek账号/deepseek-flash
  子代理 depth=1  a6api/deepseek-v4.1-flash
    孙代理 depth=2  a6api/deepseek-v4.1-flash
      禁止创建、委派或启动任何代理
```

使用执行平台实际支持的参数显式请求模型，记录返回的实际路由。不要改写上述标识，不要向工具传不存在的参数，也不要用会继承母代理模型的工具冒充正确子模型。无法核验身份时如实写“路由已请求，实际模型未能核验”；路由不支持时报告具体能力缺口，不自行换模型。

若平台不允许子代理创建孙代理，由你将相同小任务作为直接子任务派发，并记录实际为两层。孙任务必须有明确父任务、独立文件范围和全局并发名额。母、子、孙总并发建议最多 4 个；不允许每个子代理各自额外开满槽位。

开发代理模型与游戏里的脚本学生、未来训练模型是不同概念；游戏运行不调用这些大模型，不要求玩家登录大模型账号。

## 三、交付目标与不可混淆的边界

当前规则：单文件 demo/ustc-danmaku.html 可双击离线打开；Boss 使用官方校徽圆形遮罩；初始3学生、每清波+1至8后持续8人，出生预告120tick；Boss死亡为唯一终点，没有胜利条件。GPA只由累计真实击倒n决定，C计算floor(430*n/(n+20))，前端只读；旧每杀+.10、有限局WIN和旧四阶段GPA不得恢复。第4招成本100。用户已授权基于可复现证据调试和平衡数值，统一维护demo_config、配置版本、规则表并重测，不用逐项重复请求批准。当前最终消耗30/40/15/100，课表spread96接受时锁定到计划。


用 PixiJS 8.x/WebGL 绘制，TypeScript 处理网页输入和流程，菜单/HUD 优先 HTML/CSS；同一批纯 C 源码通过 Emscripten 编译为 Wasm。原生无界面 C 仿真保留给回归和以后训练。

你需要实际写代码、构建、运行、验证并交付静态包。先跑通一招，最终仍须四招、脚本学生移动躲避与反击、真实命中、共享能量、无尽派学生、击倒 GPA、死亡结算、暂停和重开。静态界面、临时桩、夹具及录像不能作为可玩验收证据。

复用既有 C 核心，不在 TS 重写运动、碰撞、AI、能量、技能或终局。核心保持 C 编译，禁止靠 C++ 编译掩盖 C 错误。前端不消耗核心随机流、不通过 Sprite 边界判命中、不修改攻击计划。

沿用既有获准规则：鼠标朝指针移动与键盘备用；单一共享能量；单招流程与接受时锁几何；学生发射时瞄 Boss、直线不追踪；无接触伤害、普通弹不穿透；同 tick Boss 与最后学生双倒也记 Boss 败；无强制时限；攻击结束只清本招 Boss 弹；本轮不启用默认场力、ddl 或擦弹。数值从同一 C 配置读取，不在 JS 再放一套默认值。

本阶段不训练模型、不建设完整训练平台，不恢复旧六秒窗口、旧 Q 表、GA 或复杂计分。不要承诺浏览器与原生性能几乎相同。

## 四、M00：并行前必须完成的冻结

先核对 `docs/web-demo-plan.md` 的实际完成状态，为本轮新增的小任务建立任务表。新增任务初始 TODO；已完成内容仅在需要修改或验证时派增量任务，不重复实现。

- 记录选定源码基线、配置版本、已有失败、工具链和可复跑命令。必要修复独立记录，不把“历史报告通过”当成当前检查。
- 冻结具体依赖版本和锁文件、同一核心编译清单、导出符号及 C/TS ABI；记录真实初始化、错误和缓冲有效期。显示快照可投影已公布预警所需几何与时序，不导出隐藏随机流或未公开未来状态；AI 观察另行规定。
- 你先提供 `wasm/build_probe.c` 和最小导出清单，让 W01 独立验证核心探针；W01 不等待 W02/W03 的完整桥接实现。正式导出清单随桥接完成后更新，探针不能算玩法验收。
- 公共桥接头、TS 共有类型、预警字段和任务卡由你维护。已有 `WorldView` 含 C 指针，必须有明确批量快照，不猜偏移和对齐。
- 64 位 seed/ID 采用明确高低位或 BigInt 协议；Wasm 内存增长后更新视图。状态、事件、预警和溢出诊断都要覆盖。
- 冻结唯一主循环与输入消费契约：固定 60 Hz；零 tick 保留边沿，多 tick 不重复出招且事件不丢；隐藏页面自动暂停，玩家继续时清零积压。
- 冻结坐标换算、页面布局和暂停/重开/终局流程；缩放不能改变物理。已有鼠标/键盘混用临时行为单独标注，不擅自改变。
- 每个文件一个写入者；记录母代理独占文件。公共入口、依赖清单/锁文件、导出和配置只由你改。需要接管实现文件时先收回原写权限。
- 共享 checkout 的切分支、暂存、提交、推送和回退只由你执行。子/孙不得操作共享 index，不得 `reset`、`clean` 或 `checkout --` 清理或回退他人修改；独立工作树另在任务卡规定 Git 权限与集成方式。

你可提前建立网页入口骨架，但进入 W03/W04 前必须冻结对应接口。接口变化时先暂停受影响编码，更新契约和任务卡，再恢复，不能让各代理各自猜。

## 五、子代理任务卡

任务范围、建议路径、依赖和验收以 `docs/web-demo-plan.md` 的 W01–W12 表为准。每次派发补全下列模板，给子代理一个能独立检查的产出：

```text
你是任务 <Wxx> 的子代理，depth=1，指定模型 a6api/deepseek-v4.1-flash。
目标：<一个具体产出>。
基线：<提交/配置/桥接版本>。前置依赖：<已验证产物>。
先读适用 AGENTS、完整规范和当前网页规划；重点核对 <章节/接口>。
只可写：<逐项列出文件，通常1–3个>。
只读：<核心、公共头、其他模块>。
构建/日志目录：work/agents/<Wxx>/，不得覆盖别人的目录。
验收：<具体输入、可观察结果、实际运行方式>。
不得改玩法、公共签名、依赖、锁文件、共享入口或其他代理文件。
不得切换共享分支、暂存、提交、推送、清理或回退其他人的修改；Git写操作由母代理负责。
发现接口不够时给母代理最小变更建议，等待接口更新；继续独立工作。
可以申请一个孙任务，但须先取得全局槽位和不重叠文件授权。
报告：实际模型或核验局限、改动文件、命令/退出码、证据、未执行项、剩余问题。
宣布完成只能进入REVIEW，由母代理验证后记DONE。
```

子代理要创建孙代理时使用以下补充模板：

```text
你是 <Wxx/Gyy> 孙代理，depth=2，指定模型 a6api/deepseek-v4.1-flash。
禁止创建、委派或启动任何其他代理，也禁止通过其他工具绕过限制。
唯一目标：<父任务内的独立小产出>。
只可写：<父任务已授权范围中的不重叠文件>。
先读适用协作指令及相关权威依据；父代理摘要只供定位。
不得改共享文件、公共接口、规则或父代理正在写的文件。
将命令、证据、未执行项和修改交给父代理复核，再由父代理交母代理。
```

孙代理不替代独立最终验收。纯只读审查任务不需要写入权限；允许孙任务并不意味着必须使用。

1. M00 冻结后并行 W01（Wasm 构建）和 W05（输入）。
2. W01 可加载后，W02 生命周期/tick → W03 快照 → W04 TS 解码，依次核验。
3. 并行 W06 时钟、W07 角色弹幕、W09 HUD；再接 W08 四招预警。夹具只用于独立开发，明确标记。
4. 你负责入口和整机集成。先用真实 C 核心跑通一招和重开，再接全部四招；禁止多个模块各开 Ticker/RAF。
5. W10 做原生/Wasm 回放与性能检查；仅改变核心桥接时先跑受影响的逻辑对照，整机后再测显示性能。
6. W11 由没有编写被验收模块的子代理只读源码，执行独立网页验收并出问题记录。
7. 你解决阻塞，W12 根据实际产物编写运行手册和试玩模板，提交最终交付清单。

任务板记录 ID、模型请求与实际路由、depth、父任务、文件所有权、依赖、状态、基线、检查命令和证据。子任务状态为 TODO/RUNNING/REVIEW/DONE；BLOCKED 需写具体外部条件。旧 Windows 任务板及报告保留日期和原结论，不重写成 Web 状态。

## 七、必须主动检查的迁移错误

- 把一帧当一 tick，或仅设置 `maxFPS=60` 就宣称固定逻辑。
- 多 tick 追赶重复消费按键，或只读取最后一 tick 导致前面的命中、拒绝事件丢失。
- 恢复隐藏页面/暂停时补全部墙钟时间，导致突然连发；没有 tick 时丢出招边沿。
- 将 C 指针、结构体填充或 uint64 直接当普通 JS 对象/number；缓存了内存增长前的旧 TypedArray。
- 前端猜预警几何、重跑随机算法、根据 Sprite 碰撞重算命中；渲染快照泄漏隐藏状态。
- 每帧创建/销毁全部 Sprite、重建复杂图形或全部 HUD；用槽下标冒充整局唯一 ID。
- 将历史 EasyX 构建、进程存活或工作集数字当网页实际操作/FPS证据；把 800 发夹具写成正常四招弹量。
- 将静态页面打不开归咎于核心，而未检查 HTTP、Wasm MIME、资源相对路径、加载顺序及浏览器控制台。
- 操作共享 Git index 或切换分支，破坏其他任务的工作；以清理失败构建为由删除他人源码和记录。

首版普通 Sprite 对象池、共享图集与 WebGL 足够作为起点；性能采样后再决定粒子容器等优化，不先建设通用框架。

## 八、验收、训练边界与最终回复

按 `docs/web-demo-plan.md` 的验收门槛执行。原生/Wasm 回放比较逐 tick 稳定字段、事件和终态，不比较含指针和填充的内存字节；浮点容差提前记录，离散事件分歧必须排查。

性能检查使用 Release，在明确机器、浏览器、DPR、分辨率和时长下测常规对局及 800 发夹具，分开报告核心、桥接、绘制、整帧和原生仿真吞吐。不能只有平均 FPS，也不能将未执行写成通过。

训练继续用原生 C 核心。后续仍需设计观察、动作、决策调度、奖励、重置、终止/截断和批量环境；本阶段的渲染快照不是训练观察，脚本 sim 不是已完成的 RL 环境。

最后交付：源码与锁文件、可复制构建/HTTP试玩命令、静态包、真实键位、旧调试记录索引、独立验收报告和已知问题。最终回复说明已实现、已验证和待测的内容，给实际产物位置；仅有计划或截图不能宣称网页可玩版完成。
