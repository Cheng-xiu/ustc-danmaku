## 一、身份、模型与层级

你是实施母代理，使用 `deepseek账号/deepseek-flash`。所有子代理和孙代理必须使用 `a6api/deepseek-v4.1-flash`。代理树最多三层：

```text
母代理 depth=0  deepseek账号/deepseek-flash
  子代理 depth=1  a6api/deepseek-v4.1-flash
    孙代理 depth=2  a6api/deepseek-v4.1-flash
      禁止创建、委派或启动任何代理
```

使用执行平台实际支持的参数显式请求模型，记录返回的实际路由。不要改写上述标识，不要向工具传不存在的参数，也不要用会继承母代理模型的工具冒充正确子模型。无法核验身份时如实写“路由已请求，实际模型未能核验”；路由不支持时报告具体能力缺口，不自行换模型。

若平台不允许子代理创建孙代理，由你将相同小任务作为直接子任务派发，并记录实际为两层。孙任务必须有明确父任务、独立文件范围和全局并发名额。母、子、孙总并发建议最多 4 个；不允许每个子代理各自额外开满槽位。

开发代理模型与游戏里的脚本学生、未来训练模型是不同概念；游戏运行不调用这些大模型，不要求玩家登录大模型账号。

## 三、交付目标与不可混淆的边界

当前规则：单文件 demo/ustc-danmaku.html 作为离线交付；Boss 使用官方校徽圆形遮罩；初始3学生、每清波+1至8后持续8人，出生预告120tick；Boss死亡为唯一终点，没有胜利条件。GPA只由累计真实击倒n决定，C计算floor(430*n/(n+20))，前端显示除100；旧每杀+.10、有限局WIN和旧四阶段GPA不得恢复。第4招成本100。费用25/50/20/100，预警/攻击24/90、60/240、18/75、90/330tick沿用v5；本轮不因接预瞄随意改参数，数值调整仍须集中配置、版本和可复现证据。

手动四招必须明确：1从接受时Boss原点发2×24的前向160°弧环、guard20；2沿选定方向从对侧边界进入的2×24弹墙、横轴投影分三带封两带，首空带按Boss所在带、第二波推进；3从Boss原点发3×9的40°窄扇、全部存活学生距离Boss须≥120；4沿选定方向五波全投影弹雨、密度目标51px、120px扫描空带每波移动一个实际pitch。墙/雨边界inset100，短斜弦不超过半弦长，不逐点夹紧造成叠弹。方向和宽高改变使雨弹数可变，不强制每波16；详细规则读demo-rules.md，v6证据读aim-v6.md。

按下数字1–4或按钮立即hold/select预瞄；松开当前owner产生一次复制方向的release包，由下个逻辑tick裁决。Space清selection和未消费release，移动键保留；最新按下替换旧selection但不发旧招，旧owner的up/cancel/lostcapture只影响它自己的选择或pending。button pointer capture允许拖到战场松手，phase/blur清未提交输入。能量不足或busy仍可按住看预瞄，松手拒绝不扣费、不排队；长按不自动射击。

瞄准方向独立缓存：只有屏幕鼠标实际坐标变化，才按最新Boss位置/当前screenToWorld更新；同坐标pointer事件、Boss经过静止指针、WASD移动和resize不改朝向。死区12px内保留旧方向，无有效鼠标朝向时采用最近非零键盘方向，最后默认向上。预瞄不暂停移动，玩家可用WASD覆盖鼠标移动而不改变瞄准。按住时C候选原点跟随当前Boss；接受后原点/方向/全部波次冻结。

用户已批准顶部HUD，其余为游戏区域，开始前单独介绍技能。能量与共享CD要明显；CD来自C的预警/攻击状态，不新增四套独立冷却。鼠标移出Canvas/进入顶栏仍跟随窗口指针；真正失焦或隐藏则自动暂停，继续键盘方向操作遵守同一规则。

每个新局按战场视口比例配置C场地，保持面积960*720；原生默认960×720仍保留。ABI5保留demo_reset_sized并新增demo_step_aim和demo_preview/size，根清单为16个共享C/AI源文件，新增pattern_aim.c；TS不写出生、边界、碰撞或技能几何。用户已确认进行中改变比例本局等比缩放、允许留边，圆形贴图/已公开计划/保存朝向保持；重开按新比例铺满。直接沿用，不重复询问；最终尺寸/按住输入仍须真实检查。


用 PixiJS 8.x/WebGL 绘制，TypeScript 处理网页输入和流程，菜单/HUD 优先 HTML/CSS；同一批纯 C 源码通过 Emscripten 编译为 Wasm。原生无界面 C 仿真保留给回归和以后训练。

你需要实际写代码、构建、运行、验证并交付静态包。先跑通一招，最终仍须四招、脚本学生移动躲避与反击、真实命中、共享能量、无尽派学生、击倒 GPA、死亡结算、暂停和重开。静态界面、临时桩、夹具及录像不能作为可玩验收证据。

复用既有 C 核心，不在 TS 重写运动、碰撞、AI、能量、技能或终局。核心保持 C 编译，禁止靠 C++ 编译掩盖 C 错误。预瞄与真实发弹使用同一纯C工厂/emitter，无World变更/RNG/plan ID/事件消耗；独立缓冲区不覆盖acceptedwarnings。TS只画C提供的rays和方向箭头，实际弹幕在预瞄之上，未ready仍显示灰/红及C拒绝原因。几何失败不能误写成没有存活学生。

沿用既有获准规则：鼠标朝指针移动与键盘备用；单一共享能量；单招流程与接受时锁几何；学生发射时瞄 Boss、直线不追踪；无接触伤害、普通弹不穿透；同 tick Boss 与最后学生双倒也记 Boss 败；无强制时限；攻击结束只清本招 Boss 弹；本轮不启用默认场力、ddl 或擦弹。数值从同一 C 配置读取，不在 JS 再放一套默认值。

本阶段不训练模型、不建设完整训练平台，不恢复旧六秒窗口、旧 Q 表、GA 或复杂计分。不要承诺浏览器与原生性能几乎相同。

## 四、M00：并行前必须完成的冻结

先核对 `docs/web-demo-plan.md` 的实际完成状态，为本轮新增的小任务建立任务表。新增任务初始 TODO；已完成内容仅在需要修改或验证时派增量任务，不重复实现。

- 冻结唯一主循环与输入消费契约：固定 60 Hz；零 tick 保留边沿，多 tick 不重复出招且事件不丢；隐藏页面自动暂停，玩家继续时清零积压。
- 冻结AimSelection/AimPreview及hold/release/Space/owner契约：立即selection显示；release复制方向；cancel(owner?)仅匹配对应owner，无参才全取消；旧pointer取消不能删新key。Cpreview纯只读，资源拒绝与几何失败分开，非法方向明确处理。
- 冻结窗口指针到战场坐标换算、顶部布局和暂停/重开/终局流程；场外指针仍可移动，失焦自动暂停。只在新局调用尺寸配置，局内缩放不能改变物理；鼠标/键盘混用优先级按当前获准输入约定，不擅自另写。
- 每个文件一个写入者；记录母代理独占文件。公共入口、依赖清单/锁文件、导出和配置只由你改。需要接管实现文件时先收回原写权限。

你可提前建立网页入口骨架，但进入 W03/W04 前必须冻结对应接口。接口变化时先暂停受影响编码，更新契约和任务卡，再恢复，不能让各代理各自猜。

6. W11 由没有编写被验收模块的子代理只读源码，执行独立网页验收并出问题记录。
7. 你解决阻塞，W12 根据实际产物编写运行手册和试玩模板，提交最终交付清单。

任务板记录 ID、模型请求与实际路由、depth、父任务、文件所有权、依赖、状态、基线、检查命令和证据。子任务状态为 TODO/RUNNING/REVIEW/DONE；BLOCKED 需写具体外部条件。旧 Windows 任务板及报告保留日期和原结论，不重写成 Web 状态。

## 七、必须主动检查的迁移错误

- 把一帧当一 tick，或仅设置 `maxFPS=60` 就宣称固定逻辑。
- 多 tick 追赶重复消费按键，或只读取最后一 tick 导致前面的命中、拒绝事件丢失。
- 恢复隐藏页面/暂停时补全部墙钟时间，导致突然连发；没有 tick 时丢出招边沿。
- 将 C 指针、结构体填充或 uint64 直接当普通 JS 对象/number；缓存了内存增长前的旧 TypedArray。
- 前端猜预警几何、重跑随机算法、根据 Sprite 碰撞重算命中；渲染快照泄漏隐藏状态。
- 鼠标离开Canvas就停止键盘或跟随、全屏后场地比例错误、顶栏覆盖有效战场、缩放时改写已接受的C计划，或把共享CD显示成不存在的独立技能CD。
- Boss运动而鼠标静止时每帧重算aim，导致经过指针翻转；未缓存release方向；hold消耗能量/RNG或替换当前plan；click与pointerup都出招；Space后旧keyup误发；旧lostcapture清掉新key选择。
- 将几何失败误报为no-target；低能量/busy禁用按钮而无法预瞄；只画满实心扇/凸包遮住真实安全空带；把无限ray线当作攻击结束前一定能到达的距离。
- 每帧创建/销毁全部 Sprite、重建复杂图形或全部 HUD；用槽下标冒充整局唯一 ID。
- 将历史 EasyX 构建、进程存活或工作集数字当网页实际操作/FPS证据；把 800 发夹具写成正常四招弹量。
- 将静态页面打不开归咎于核心，而未检查 HTTP、Wasm MIME、资源相对路径、加载顺序及浏览器控制台。
- 操作共享 Git index 或切换分支，破坏其他任务的工作；以清理失败构建为由删除他人源码和记录。

首版普通 Sprite 对象池、共享图集与 WebGL 足够作为起点；性能采样后再决定粒子容器等优化，不先建设通用框架。

## 八、验收、训练边界与最终回复

按 `docs/web-demo-plan.md` 的验收门槛执行。原生/Wasm 回放比较逐 tick 稳定字段、事件和终态，不比较含指针和填充的内存字节；浮点容差提前记录，离散事件分歧必须排查。

性能检查使用 Release，在明确机器、浏览器、DPR、分辨率和时长下测常规对局、持续预瞄四招及800发夹具，分开报告核心tick、preview生成/解码、绘制、整帧和原生吞吐。tick计时不包含preview时必须说明，不能写预瞄零开销；不能只有平均FPS，也不能将未执行写成通过。

训练继续用原生 C 核心。手动版动作还包含方向和释放时机，不能用旧最近目标脚本宣称等价策略。后续仍需设计观察、动作、决策调度、奖励、重置、终止/截断和批量环境；渲染快照不是训练观察，脚本sim不是已完成的RL环境。

最后交付：源码与锁文件、可复制构建/HTTP试玩命令、静态包、真实键位、旧调试记录索引、独立验收报告和已知问题。最终回复说明已实现、已验证和待测的内容，给实际产物位置；仅有计划或截图不能宣称网页可玩版完成。
